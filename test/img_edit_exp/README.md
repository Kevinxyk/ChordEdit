# Image asset layout

This directory contains the image assets and run records for the ChordEdit testcase experiments.

## Layout

```text
img_edit_exp/
├── assets/source/{case_id}/
│   ├── source.png or source_gemini.jpg
│   ├── meta.jsonl
│   └── source_metadata.json
├── runs/{run_id}/
│   ├── outputs/{case_id}/seed_{seed}.png
│   └── run_records.jsonl
├── test_metadata.json
├── evaluation_template.jsonl
└── evaluation.jsonl
```

The first prepared run is `exp_001_run_001`. Keep one canonical source image per case and never overwrite it when testing another seed or model. Put those outputs under a new `run_id` instead.

Before editing, manually check each generated `source.png` against its `source_prompt`. Set `source_validated=true` only when the subject and major attributes are acceptable; leave it `null` while pending or set it to `false` when the image should not enter the formal benchmark.

Each case directory already has a `meta.jsonl` compatible with the project's existing example loader. For generated source images, fill `source_metadata.json` using `source_metadata_template.json`. The official webpage is only prompt/case provenance; its screenshot is not used as the canonical source image. Currently `ai_A1` to `ai_E3` use imported Gemini `1024x1024` images, while the remaining 15 cases are generated by the server-side SD-Turbo script. The source generation plan is `source_generation_manifest.jsonl`.

After the repository is available on the server, run:

```bash
python test/img_edit_exp/generate_sources.py \
  --model-root /root/models/sd-turbo \
  --manifest test/img_edit_exp/source_generation_manifest.jsonl
```

The script loads the model once, generates the `generate_source` records, saves each image as `source.png`, and updates its `source_metadata.json`. Existing images are skipped unless `--overwrite` is supplied.
